## Session schema

NDJSON is ordered and contains protocol-v2 input and state lines unchanged.
Each accepted advancing input tick costs 0.05 s (20 Hz, default warp 0.01;
burn pacing is 3 s as Transit specifies). A commit's dtau=0 tick is not a
transit tick: its hold is counted by one UI event. State-only streams count
positive clock.tau deltas while committed through arrival; new_game/reset
and zero-duration intent ticks cost zero. Leg boundaries are committed/arrived
journey changes. For fixtures a `sim_ticks` event has integer `ticks` and `leg`
(1-based); it compactly represents that many accepted default-paced ticks.
Future bot UI lines: `{"type":"click","action":"commit_hold"}` or
`{"type":"key","action":"..."}` (each 1.5 s, hold emitted once),
`{"type":"text_shown","words":100}` (each actual presentation, 200 wpm),
`{"type":"interactable_visit","id":"..."}` (20 s per visit).
UI fixtures do not claim that a scene was exercised. The time audit fails on
unknown event types or malformed JSON; an empty stream fails its leg band.
Archive observations use `changes.consequence.archive.unlocked`; legacy
appends supply trigger evidence. Hints are checked at first appearance against the
recorded new_game archive table (input+state session) or legacy trigger history
(state-only stream). Cumulative repeated unlock lists must preserve their prefix.
