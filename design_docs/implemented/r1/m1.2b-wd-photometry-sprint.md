**Exported API (exactly these):** `bbTeffMin` (3000.0), `bbTeffMax`
(100000.0), `bbBpRp(kelvin)` and `bbGMinusV(kelvin)` (forward quadrature,
`requires kelvin > 0`), `bbBpRpInvertible(bpRp)`, `bbClampTeff(t)` (the only
`ensures`, Z3-proved), `bbTeffFromBpRp(bpRp)` (61-node table, wraps
`bbClampTeff`, **no** `ensures`), `bbTeffFromBpRpExact(bpRp)` (48-step ln-T
bisection; tests and tools only), `bbGMinusVFromBpRp(bpRp)` (tests
`bpRp == bpRp` FIRST; NaN → the 3000 K end node), `bbVFromG(g, bpRp)`.

**Implementation rules (measured, binding):**
- **NaN tested first with `c == c`** (row A4: the v0.47.2 interpreter
  evaluates `NaN > 1.0` as true, the VM as false).
- **No nested cons patterns** (row V2): `a :: b :: rest` is evaluator-only
  and fails `--strict-bytecode`. Single-level `x :: rest`, carrying the
  previous node as an argument (the prototype's `interpFrom(c, x0, y0, xs,
  ys)` shape).
- **Contract placement** (rows Z1–Z2): Z3 skips an `ensures` on any function
  whose body calls a recursive list-walking helper, so the range guarantee
  lives on `bbClampTeff` (verified); `bbTeffFromBpRp` wraps its result in it
  and carries no `ensures`; check12 tests the range empirically.
- **Quadrature:** walk each response list with an accumulator by pattern
  match; subtract the ½(first + last) trapezoid terms; never `nth_or` inside
  a loop; the table interpolation walks the three node lists in one pass.
- **Test style:** test blocks call named `checkNN()` functions (CLAUDE.md
  float-literal workaround).

**Tasks (test-first):**
1. Write `blackbody_photometry_test.ail` first, check01–check12, using the

   expected values from the implementation under test.
2. Implement `blackbody_photometry.ail` until all checks pass on the
